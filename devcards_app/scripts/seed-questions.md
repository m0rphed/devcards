## SQL

**1. basic** — `HAVING` vs `WHERE`
- Front: Что делает `HAVING` в SQL и чем отличается от `WHERE`?
- Back:
  - `WHERE` фильтрует строки **до** группировки (`GROUP BY`)
  - `HAVING` фильтрует уже **агрегированные** группы, после `GROUP BY`
  ```sql
  SELECT dept, COUNT(*) FROM employees
  GROUP BY dept
  HAVING COUNT(*) > 5;
  ```

**2. basic** — что вернёт запрос
- Front:
  ```sql
  SELECT * FROM users WHERE age > 18 ORDER BY age DESC LIMIT 3;
  ```
  Что вернёт этот запрос?
- Back: Три строки — пользователи старше 18, отсортированные по возрасту **по убыванию**,
  показаны только первые 3.

**3. cloze**

  удовлетворяющих условию.

**4. multiple_choice** — что НЕ является типом JOIN
- Question: Что из перечисленного **не** является типом `JOIN` в SQL?
- Options: `INNER JOIN` | `LEFT JOIN` | `CROSS JOIN` | `FULL SIDE JOIN`
- Correct: `FULL SIDE JOIN` (index 3) — не существует, есть `FULL OUTER JOIN`

**5. basic** — DELETE vs TRUNCATE vs DROP (таблица)
- Front: Чем отличаются `DELETE`, `TRUNCATE` и `DROP`?
- Back:

  | Команда  | Удаляет      | Откатить (ROLLBACK) | Сбрасывает auto-increment |
  |----------|--------------|----------------------|---------------------------|
  | `DELETE` | строки       | да                   | нет                       |
  | `TRUNCATE` | все строки | обычно нет           | да                        |
  | `DROP`   | всю таблицу  | нет                  | —                         |

**6. multiple_choice** — индекс для полнотекстового поиска
- Question: Какой тип индекса в PostgreSQL лучше всего подходит для полнотекстового
  поиска по `tsvector`?
- Options: `B-tree` | `GIN` | `Hash` | `BRIN`
- Correct: `GIN` (index 1)

## Go

**1. basic** — порядок `defer`
- Front:
  ```go
  func main() {
      defer fmt.Println("1")
      defer fmt.Println("2")
      fmt.Println("3")
  }
  ```
  Что выведет этот код и в каком порядке?
- Back:
  ```
  3
  2
  1
  ```
  `defer` выполняется в порядке **LIFO** — последний вызванный `defer` срабатывает первым.

**2. multiple_choice** — запись в закрытый канал
- Question: Что произойдёт при попытке записи в уже закрытый (`close()`) канал?
- Options: Значение молча потеряется | `panic: send on closed channel` | Горутина
  заблокируется навсегда | Канал автоматически откроется заново
- Correct: `panic: send on closed channel` (index 1)

**3. cloze**
- Text: Горутины в Go — это {{c1::легковесные потоки выполнения}}, которыми управляет
  сам рантайм, а не операционная система.

**4. basic** — nil slice vs пустой slice
- Front: В чём разница между `nil`-slice и **пустым** slice в Go?
  ```go
  var a []int      // nil
  b := []int{}     // пустой, но не nil
  ```
- Back:
  - `len(a) == 0` и `len(b) == 0` — оба «пустые» по длине
  - Но `a == nil` → `true`, а `b == nil` → `false`
  - Некоторые API (например, сериализация в JSON) различают эти два случая:
    `nil` → `null`, пустой slice → `[]`

**5. multiple_choice** — примитив синхронизации
- Question: Какой примитив синхронизации предотвращает гонку данных при доступе к общей
  переменной из нескольких горутин?
- Options: `sync.WaitGroup` | `sync.Mutex` | `context.Context` | `sync.Once`
- Correct: `sync.Mutex` (index 1)

**6. basic** — неявная реализация интерфейсов
- Front: Нужно ли в Go явно объявлять, что тип реализует интерфейс?
- Back: Нет — интерфейсы реализуются **неявно** (structural typing): если у типа есть
  все нужные методы с нужными сигнатурами, он автоматически удовлетворяет интерфейсу,
  никакого `implements` не требуется.

**7. cloze**
- Text: Ключевое слово {{c1::defer}} откладывает вызов функции до момента выхода из
  окружающей функции.

**8. multiple_choice** — проверка обёрнутой ошибки
- Question: Как принято проверять конкретный тип/значение ошибки, обёрнутой через
  `fmt.Errorf("...: %w", err)`?
- Options: `err == MyError` | `errors.Is(err, MyError)` | `err.(MyError)` напрямую |
  `panic(err)`
- Correct: `errors.Is(err, MyError)` (index 1)

## JavaScript

**1. basic** — приведение типов
- Front:
  ```js
  console.log("10" + 2 * "5");
  ```
  Что выведет этот код?
- Back: `"1010"` — сначала `2 * "5"` приводит строку `"5"` к числу и даёт `10`, затем
  `"10" + 10` **конкатенирует** строки (число снова приводится к строке).

**2. multiple_choice** — сохранение порядка ключей
- Question: Какая структура данных в JS специально спроектирована так, чтобы сохранять
  порядок вставки ключей **любого** типа (включая объекты)?
- Options: `Object` | `Map` | `WeakMap` | `Array`
- Correct: `Map` (index 1)

**3. cloze**
- Text: {{c1::Замыкание (closure)}} — функция, которая запоминает переменные из своей
  лексической области видимости даже после завершения внешней функции.

**4. basic** — hoisting
- Front: Чем `let`/`const` отличаются от `var` в контексте `hoisting`?
- Back:
  - `var` — поднимается и сразу инициализируется как `undefined`, область видимости —
    **функция**
  - `let`/`const` — тоже поднимаются, но попадают в *temporal dead zone* до самого
    объявления, область видимости — **блок**

**5. multiple_choice** — порядок выполнения (event loop)
- Question:
  ```js
  console.log('A');
  setTimeout(() => console.log('B'), 0);
  Promise.resolve().then(() => console.log('C'));
  console.log('D');
  ```
  В каком порядке это выведется?
- Options: `A, B, C, D` | `A, D, C, B` | `A, D, B, C` | `D, A, C, B`
- Correct: `A, D, C, B` (index 1) — микротаски (`Promise`) выполняются раньше
  макротасков (`setTimeout`), даже с задержкой `0`

**6. basic** — поверхностное копирование
- Front: Как сделать поверхностную (`shallow`) копию объекта одной строкой?
- Back:
  ```js
  const copy = { ...original };
  ```
  Спред-оператор копирует **собственные перечисляемые** свойства верхнего уровня —
  вложенные объекты остаются общими по ссылке.

**7. cloze**
- Text: Метод массива {{c1::reduce}} сворачивает все элементы в одно значение, передавая
  аккумулятор от итерации к итерации.

**8. multiple_choice** — tree shaking
- Question: Что делает `tree shaking` в сборщиках вроде Webpack/Rollup/Vite?
- Options: Сортирует импорты по алфавиту | Удаляет неиспользуемый код из финального
  бандла | Разбивает бандл на чанки по роутам | Минифицирует имена переменных
- Correct: Удаляет неиспользуемый код из финального бандла (index 1)
